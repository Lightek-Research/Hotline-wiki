Аддоны

Аддон связывает HOTLINE с другой системой: принимает её команды во время записи и вызывает её API при воспроизведении. GLights продолжает работать как раньше. Например, одно шоу может содержать свет, камеры, текст песни и пиро.

Для этой функции нужен HOTLINE 0.14.0 или новее. Готовый аддон — ModuleScript для папки Addons. Сами внешние системы устанавливаются отдельно.

Установка готового аддона

  1. Остановите Play.
  2. Импортируйте .rbxmx аддона. Перенесите сам ModuleScript в ServerScriptService → Hotline → Addons.
  3. Установите внешнюю систему и проверьте путь к её API.
  4. Запустите Play заново и проверьте статус аддона.
  5. Создайте кью в Edit, включите запись и управляйте внешней системой обычным способом.

Устанавливайте одну копию каждого аддона. Текстовый .luau-файл в архиве обычно является исходником того же модуля, а не второй обязательной частью установки. Старые скрипты аддонов StacyPilot автоматически совместимыми не становятся: для HOTLINE нужны адаптированные модули.

Доступные интеграции

АддонAPI по умолчаниюЧто записывает
LyricsServerScriptService.LyricsController.Scripts.ApiИзменение текста через LineChanged; воспроизводит Chat(text).
CamerasWorkspace.CameraSystem.ApiКамера, фокус, FOV, blur, saturation, tilt, bars, blackout, transition/speed и shake.
Пиро: учебный примерWorkspace.Fire и Workspace.PyroButtonВключение/выключение ParticleEmitter. Полный модуль — в руководстве создания аддонов.

Lyrics и Cameras адаптированы по присланным интеграциям StacyPilot. Их специальные графические треки не переносятся: используются стандартные Events и Cue List HOTLINE.

PyroTemplate в основной сборке — выключенная заготовка. Для реальной пиротехники нужно реализовать её настоящий API. Это не готовый универсальный драйвер.

Пути и настройки

Добавьте настройки внутрь существующей таблицы Config. Если AddonOptions уже существует, дополните его, а не создавайте второе поле с тем же именем.

AddonOptions = {
    Lyrics = {
        ApiPath = "ServerScriptService.LyricsController.Scripts.Api",
    },
    Cameras = {
        ApiPath = "Workspace.CameraSystem.Api",
        SnapshotOnRecord = false,
    },
},

Без этих полей используются пути по умолчанию. При наличии Snapshot в самом аддоне параметр SnapshotOnRecord=true добавляет начальное состояние в начале Timed. В Capture автоматический снимок не делается: система ждёт вашу команду.

После изменения путей или установки зависимости перезапустите тест. Если внешний API отсутствовал при загрузке, автоматически повторное подключение не выполняется.

Timed и Capture

РежимПоведение
TimedКоманды записываются с реальными временными смещениями относительно начала кью. Pause завершает запись.
CaptureПервая команда записывается на смещении 0, после чего запись автоматически заканчивается.

Если одно действие пульта вызывает несколько сигналов, Capture сохраняет первый. Это не пакетный снимок всех параметров. Для последовательности используйте Timed.

Откройте Events выбранной кью. Цели аддонов начинаются с @: @Lyrics, @Cameras, @Pyro. Не используйте этот префикс в именах групп GLights. Во время воспроизведения команды HOTLINE не должны повторно записывать себя. Шоу с событиями аддона требует установленной рабочей интеграции; без неё загрузка отклоняется.

Один пример: пиро

В руководстве создания аддонов показан полный путь: обычная кнопка включает/выключает эмиттеры в Workspace.Fire → добавляем emit для записи → регистрируем On/Off для воспроизведения. В конце есть полный код одного ModuleScript Pyro.

Отдельный API пиро этому примеру не нужен. Создайте Fire с настроенными ParticleEmitter, PyroButton с ClickDetector и установите модуль. Записывается действие кнопки один раз, а не каждое изменение эмиттера.

Сброс и перемотка

Каждый аддон определяет свой Reset. Lyrics очищает текст. Cameras снимает фокус, blackout и bars, но сохраняет выбранную камеру: в присланном API не определён надёжный возврат к игровой камере. Пиро из руководства выключает ParticleEmitter.

Перемотка восстанавливает только команды, для которых разработчик включил ReplayOnSeek. Это подходит для цвета и состояния. Разовые эффекты по умолчанию пропускаются при восстановлении позиции. Подробнее для разработчиков.

Проверка состояния

Пример выполняется из обычного серверного Script:

local Api = require(game.ServerScriptService.Hotline.Scripts.Api)
assert(Api.WaitForReady(20), "HOTLINE is not ready")

local addons, err = Api.GetAddons()
if addons then
    for name, info in pairs(addons) do
        print(name, info.state, info.error)
    end
else
    warn(err)
end

WaitForReady ждёт API HOTLINE, а не все интеграции. При старте статус аддона ещё может быть loading; проверьте снова через небольшой интервал или подпишитесь на Events.AddonsChanged.

СтатусЗначение
loadingИнициализация ещё идёт.
readyАддон зарегистрирован и доступен.
missingНе найден внешний API. Проверьте путь и наличие системы.
disabledВ возвращённой таблице аддона Enabled=false.
failedОшибка структуры, подключения или таймаут регистрации. Подробности в Output.

Для отключения поставьте Enabled=false в таблице модуля и перезапустите Play. Атрибут ModuleScript Enabled=false тоже отключает загрузку; такой модуль пропускается и может отсутствовать в списке статусов.

Если события не появляются, проверьте готовность аддона, режим Edit, выбранную кью, активную запись, выполнение команд на сервере и использование правильного API. Если аддон не работает в реальной игре, отправьте шаги воспроизведения, Output и GetAddons в Telegram @hoomlion или Discord hoomlion.
