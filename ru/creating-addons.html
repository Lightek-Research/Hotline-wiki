Создание аддонов: пример с пиро

Скачать готовый модуль Pyro · ZIP

Разберём один законченный пример: кнопка включает и выключает игровые эффекты ParticleEmitter в папке Fire. Сначала кнопка только управляет эффектом. Затем мы добавим запись действий в HOTLINE и их воспроизведение из кью.

Нужен HOTLINE 0.14.0 или новее. Это пример непрерывного эффекта Enabled=true/false, а не разового ParticleEmitter:Emit(). На его основе можно подключить собственную систему. Об установке готовых аддонов.

1. Подготовьте эффект и кнопку

  1. В Workspace создайте папку Fire.
  2. Поместите в неё ваши Part/Attachment с настроенными ParticleEmitter. Аддон ищет все эмиттеры внутри папки, включая вложенные объекты.
  3. Изначально выключите у них Enabled. Проверьте вручную, что при включении эмиттер виден: текстура, Rate и остальные параметры должны быть настроены.
  4. В Workspace создайте Part PyroButton, а внутри него — ClickDetector.

Должны получиться пути Workspace.Fire и Workspace.PyroButton.ClickDetector. При тестировании в Studio левый клик будет включать эффект, правый — выключать. Кнопка должна быть в пределах MaxActivationDistance ClickDetector.

2. Как обычная кнопка работает без записи

До подключения HOTLINE серверный Script внутри PyroButton мог выглядеть так:

local folder = workspace:WaitForChild("Fire")
local click = script.Parent:WaitForChild("ClickDetector")

click.MouseClick:Connect(function()
    for _, object in ipairs(folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = true end
    end
end)

click.RightMouseClick:Connect(function()
    for _, object in ipairs(folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = false end
    end
end)

Этот код только включает и выключает эффект. HOTLINE пока не знает, какую кнопку нажали. Дальше перенесём управление кнопкой в ModuleScript-аддон; старый Script нужно отключить или удалить, иначе он продолжит выполнять действия отдельно от аддона.

Фрагменты ниже объясняют устройство. Для установки достаточно полного модуля в разделе 6 — не нужно создавать отдельный Script для каждого фрагмента.

3. Вынесите действия в функции

Нам нужны две функции, которые можно вызвать как от кнопки, так и при воспроизведении. api.Folder — ссылка на папку Fire, которую передаст Resolve.

local function turnOn(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = true end
    end
end

local function turnOff(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = false end
    end
end

Записывать нужно действие «включить пиро» один раз, а не отдельное изменение каждого эмиттера. Поэтому emit вызывается после функции, а не внутри цикла.

4. Сообщите HOTLINE о нажатии

В Connect загрузчик передаст функцию emit. После выполнения действия вызываем emit("On") или emit("Off"). Во время Timed HOTLINE сохранит время команды; в Capture первая команда завершит запись.

api.Click.MouseClick:Connect(function(player)
    if not canUse(player) then return end
    turnOn(api)
    emit("On")
end)

api.Click.RightMouseClick:Connect(function(player)
    if not canUse(player) then return end
    turnOff(api)
    emit("Off")
end)

canUse в полном коде использует whitelist HOTLINE. Он проверяет игрока до включения эффекта. Если запись выключена, разрешённая кнопка всё равно управляет пиро, но новые события в кью не добавляются.

5. Подключите воспроизведение

Название в emit должно совпадать с ключом Commands. При встрече @Pyro / On HOTLINE проверит отсутствие аргументов и вызовет turnOn. Для Off — turnOff.

Addon.Commands.On = {
    Validate = noArguments,
    Run = turnOn,
    ReplayOnSeek = true,
}
Addon.Commands.Off = {
    Validate = noArguments,
    Run = turnOff,
    ReplayOnSeek = true,
}

ReplayOnSeek=true здесь подходит, потому что Enabled — состояние, которое нужно восстановить при перемотке. Для разового залпа через Emit или другой одноразовой команды обычно оставляют false. Это не второй пример: такая команда требует отдельной реализации API вашей системы.

6. Полный код аддона

Остановите Play. В ServerScriptService → Hotline → Addons создайте ModuleScript с именем Pyro. Вставьте весь код ниже. Исходный Script кнопки из раздела 2 должен быть отключён.

-- HOTLINE 0.14.0+: continuous ParticleEmitter on/off example.
-- Install this ModuleScript as Hotline.Addons.Pyro.
local Addon = {Id = "Pyro", Version = 1, Enabled = true, Commands = {}}

local function turnOn(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = true end
    end
end

local function turnOff(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = false end
    end
end

local function noArguments(args)
    assert(args.n == 0, "Pyro On/Off do not accept arguments")
end

Addon.Commands.On = {
    Validate = noArguments,
    Run = turnOn,
    ReplayOnSeek = true,
}
Addon.Commands.Off = {
    Validate = noArguments,
    Run = turnOff,
    ReplayOnSeek = true,
}

function Addon.Resolve(context)
    local folder = context.Resolve(context.Options.FolderPath or "Workspace.Fire")
    local button = context.Resolve(context.Options.ButtonPath or "Workspace.PyroButton")
    if not folder or not button then return nil end
    local click = button:FindFirstChildOfClass("ClickDetector")
    assert(click, "PyroButton needs a ClickDetector")
    return {Folder = folder, Click = click}
end

function Addon.Connect(api, emit, context)
    local scripts = context.Root.Scripts
    local settings = require(scripts.SecuritySettings)
    local canUse = require(scripts.AccessPolicy).new(context.Config, settings)

    return {
        api.Click.MouseClick:Connect(function(player)
            if not canUse(player) then return end
            turnOn(api)
            emit("On")
        end),
        api.Click.RightMouseClick:Connect(function(player)
            if not canUse(player) then return end
            turnOff(api)
            emit("Off")
        end),
    }
end

function Addon.Reset(api)
    turnOff(api)
end

return Addon

Resolve находит эффект и кнопку. Отдельный API-модуль пиро для этого простого примера не нужен: функции включения/выключения находятся прямо в аддоне. Connect подписывается на кнопку и возвращает соединения загрузчику. Reset выключает все эмиттеры при сбросе HOTLINE.

Если вы используете другую систему, заменяйте turnOn/turnOff её реальными вызовами. Не вставляйте сюда core:Record или RegisterResponse из StacyPilot: в HOTLINE используются emit и Commands.

7. Запишите и воспроизведите

  1. Перезапустите Play после установки. Зайдите под пользователем из whitelist HOTLINE.
  2. Создайте кью в Edit, выберите Timed и нажмите Record.
  3. Левым кликом включите пиро. Через пару секунд правым кликом выключите.
  4. Нажмите Pause в HOTLINE, откройте Events.
  5. Должны появиться две команды: @Pyro / On и @Pyro / Off с разными временными смещениями.
  6. Сохраните шоу и запустите Play. Эффект должен включиться и выключиться уже без нажатия кнопки.

Для Capture нажмите Record, затем один раз включите пиро. Сохранится только On на смещении 0, запись закончится. Для длительности эффекта нужны обе команды On и Off, поэтому последовательность удобнее записывать в Timed. Stop выключает эмиттеры через Reset.

Повторное нажатие On тоже записывается как отдельное действие. Воспроизведение само себя не записывает: Run не нажимает кнопку и не вызывает emit.

Пути, статус и частые ошибки

Если имена отличаются, дополните существующую таблицу Config:

AddonOptions = {
    Pyro = {
        FolderPath = "Workspace.Fire",
        ButtonPath = "Workspace.PyroButton",
    },
},

Если AddonOptions уже есть, добавьте Pyro внутрь него. После изменения путей перезапустите тест. Один Id Pyro должен использоваться только одним включённым аддоном. Выключенный PyroTemplate из базовой сборки можно оставить выключенным.

Статус можно проверить из обычного серверного Script:

local Api = require(game.ServerScriptService.Hotline.Scripts.Api)
assert(Api.WaitForReady(20), "HOTLINE is not ready")
local addons, err = Api.GetAddons()
if addons then
    local info = addons.Pyro
    print(info and info.state, info and info.error)
else
    warn(err)
end

Аддон должен перейти в ready. Сразу после старта возможен loading: WaitForReady ждёт сервер HOTLINE, а не все аддоны. missing означает отсутствие папки/кнопки; failed — ошибку подключения, например отсутствующий ClickDetector. Все статусы.

Что менять для своего аддона

Id задаёт цель @Pyro и ключ Config.AddonOptions.Pyro. Commands перечисляет разрешённые команды. Validate получает распакованные аргументы с полем n и должен выбрасывать assert/error при неверных данных. Run получает результат Resolve и аргументы. Connect отвечает за запись; Reset — за сброс.

Для этого примера аргументов нет, поэтому проверяется args.n==0. Для другой системы проверяйте число, тип и диапазон каждого аргумента. Кодек HOTLINE поддерживает до 12 аргументов; действуют общие лимиты значений и событий.

Модули аддонов — доверенный серверный код. Resolve/Connect только подключают систему, не запускают эффекты. Обработчики и Run должны быть короткими и без ожиданий. Перед выпуском проверьте запись Timed/Capture, сохранение, загрузку, Stop, перемотку и отсутствие доступа у игрока вне whitelist.
