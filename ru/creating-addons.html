Создание аддонов

Скачать все три файла учебного примера. В архиве указано, куда положить каждый модуль; тестовый Script выключен.

В этом руководстве мы сделаем простую серверную систему с состоянием «включено/выключено», подключим её к HOTLINE и запишем команды. Это учебный пример: реальная интеграция использует API вашей камеры, пиротехники, экранов или другой системы.

Перед началом установите HOTLINE 0.14.0 и проверьте обычную запись GLights. Для использования готовых интеграций достаточно страницы аддонов.

Как устроена связь

Внешняя система сообщает об изменении → Connect передаёт команду через emit → HOTLINE сохраняет её в кью. При воспроизведении HOTLINE проверяет аргументы через Validate и вызывает Run. Reset отвечает за сброс состояния.

Аддон не заменяет API вашей системы и не должен заново создавать таймлайн. Достаточно описать фиксированный набор команд и подключить уведомления о действиях.

Шаг 1. Учебная система

Создайте ModuleScript ExampleSystem непосредственно в ServerScriptService и вставьте:

local changed = Instance.new("BindableEvent")
changed.Name = "Changed"
changed.Parent = script

local enabled = false
local System = {Changed = changed.Event}

function System:SetEnabled(value)
    assert(type(value) == "boolean", "Expected boolean")
    if enabled == value then return end
    enabled = value
    print("ExampleSystem enabled:", enabled)
    changed:Fire(enabled)
end

function System:GetEnabled()
    return enabled
end

return System

Пока система только печатает состояние в Output. В реальном продукте SetEnabled управляет прибором, а Changed сообщает об изменении. Методы этой учебной системы вызываются через двоеточие.

Шаг 2. Полный аддон

Создайте ModuleScript Example внутри ServerScriptService.Hotline.Addons. Вставьте весь код:

local Addon = {
    Id = "Example",
    Version = 1,
    Enabled = true,
    Commands = {},
}

Addon.Commands.SetEnabled = {
    ReplayOnSeek = true,
    Validate = function(args)
        assert(args.n == 1 and type(args[1]) == "boolean",
            "Example.SetEnabled expects one boolean")
    end,
    Run = function(api, value)
        api:SetEnabled(value)
    end,
}

function Addon.Resolve(context)
    return context.RequireApi("ServerScriptService.ExampleSystem")
end

function Addon.Connect(api, emit)
    assert(api.Changed and type(api.SetEnabled) == "function",
        "ExampleSystem API is incompatible")
    return {
        api.Changed:Connect(function(value)
            emit("SetEnabled", value)
        end),
    }
end

function Addon.Reset(api)
    api:SetEnabled(false)
end

function Addon.Snapshot(api, emit)
    emit("SetEnabled", api:GetEnabled())
end

return Addon

Цель событий этого аддона — @Example. Строка SetEnabled в emit должна точно совпадать с ключом в Commands. Id определяет цель и ключ настроек, а имя ModuleScript — строку в GetAddons. В примере оба имени одинаковые, чтобы не путаться.

Шаг 3. Тестовая последовательность

В ServerStorage создайте обычный Script ExampleTest и отключите его: Enabled=false. Вставьте:

local Api = require(game.ServerScriptService.Hotline.Scripts.Api)
assert(Api.WaitForReady(20), "HOTLINE is not ready")

local deadline = os.clock() + 15
while true do
    local addons, err = Api.GetAddons()
    assert(addons, err)
    local status = addons.Example
    if status and status.state == "ready" then break end
    if status and status.state ~= "loading" then
        error("Example addon: " .. status.state .. " / " .. tostring(status.error))
    end
    assert(os.clock() < deadline, "Example addon is not ready")
    task.wait(0.1)
end

local System = require(game.ServerScriptService.ExampleSystem)
System:SetEnabled(true)
task.wait(2)
System:SetEnabled(false)

Перезапустите Play после добавления модулей. В HOTLINE создайте кью, выберите Timed и нажмите Record. В серверной Command Bar запустите копию теста:

local test = game.ServerStorage.ExampleTest:Clone()
test.Enabled = false
test.Parent = game.ServerScriptService
test.Enabled = true

Через две секунды нажмите Pause в HOTLINE. В Events должны быть две команды @Example / SetEnabled: true, затем false примерно через 2 секунды. Сохраните и воспроизведите шоу — Output повторит изменения. При сбросе могут появляться дополнительные сообщения о выключении: Reset тоже управляет системой.

Для Capture сбросьте систему в false, нажмите Record в Capture и выполните включение: первая команда запишется на смещении 0. Второе действие уже не попадёт в завершившуюся запись.

Шаг 4. Начальное состояние и настройки

Чтобы перед Timed записывать текущее состояние, добавьте в существующую таблицу Config:

AddonOptions = {
    Example = {
        SnapshotOnRecord = true,
    },
},

Snapshot сам по себе не включает систему: он вызывает emit с текущим значением. HOTLINE вызывает его только для Timed при включённой настройке. Для Capture снимок не создаётся. Если AddonOptions уже есть, добавьте Example внутрь него.

Можно сделать путь настраиваемым. Тогда замените Resolve на:

function Addon.Resolve(context)
    return context.RequireApi(context.Options.ApiPath
        or "ServerScriptService.ExampleSystem")
end

Контракт модуля

ЧастьНазначение
IdУникальный идентификатор до 50 символов: первая буква, далее латинские буквы, цифры, _ или -.
Enabledfalse отключает модуль после перезапуска.
CommandsНепустая таблица фиксированных команд. У каждой обязательны Validate и Run.
Resolve(context)Возвращает API внешней системы или nil, если зависимость отсутствует.
Connect(api, emit, context)Необязательное подключение записи; возвращает массив соединений с Disconnect.
Reset(api)Необязательное безопасное восстановление/выключение при сбросе.
Snapshot(api, emit)Необязательная запись текущего состояния перед Timed.
ReplayOnSeektrue разрешает восстановление этой команды при перемотке; по умолчанию false.

Connect без реализации записи может быть полезен для ручного добавления событий через Events. Если запись нужна, без emit HOTLINE не узнает о действиях.

context.Config — Config HOTLINE. context.Options — Config.AddonOptions[Id] или пустая таблица. context.Root — корневая папка Hotline. context.Resolve(path) ищет Instance по пути; context.RequireApi(path) требует найденный ModuleScript или возвращает nil, если его нет.

Поддерживаемые корни путей: Workspace/workspace, ServerScriptService, ServerStorage, ReplicatedStorage. Путь разбивается по точкам: для объектов с точкой в имени используйте собственный Resolve с прямым FindFirstChild. Вложенные имена с пробелами и скобками поддерживаются, если в них нет точки.

Аргументы и проверка

emit принимает обычные Lua/Roblox значения, не JSON и не готовые теги:

emit("SetEnabled", true)
-- Для команды с двумя аргументами могло бы быть:
-- emit("SetColor", "Front", Color3.fromRGB(255, 0, 0))

Пример SetColor выше иллюстрирует формат: чтобы им пользоваться, сначала добавьте эту команду в Commands.

Validate получает распакованную таблицу аргументов. Поле args.n хранит их исходное количество, включая nil. Ошибку нужно выбрасывать через assert/error: возврат false сам по себе команду не отклоняет. Run получает API и аргументы обычными параметрами.

Проверяйте число аргументов, типы, имена допустимых эффектов и реальные диапазоны системы. Для чисел исключайте NaN и бесконечность. Для ссылок проверяйте, что объект относится к нужной системе. Не выбирайте произвольный метод API из пользовательской строки.

Доступно до 12 аргументов: nil, boolean, конечные числа, строки, ограниченные таблицы и поддерживаемые Color3/Vector3/ColorSequence. Ограничения кодека и PayloadGuard действуют и для аддонов; строки при декодировании ограничены 4000 байтами. Произвольные Instance не поддерживаются: существующий декодер ссылок допускает Workspace BasePart. Сохранённые аргументы сериализуются общим кодеком HOTLINE.

Если в системе нет сигналов

Предпочтителен собственный сигнал об успешной команде. Когда есть только таблица функций, можно обернуть конкретные известные методы, как в AtomLazers:

function Addon.Connect(api, emit)
    local original = api.SetEnabled
    local wrapper = function(self, value)
        assert(type(value) == "boolean", "Expected boolean")
        original(self, value)
        emit("SetEnabled", value)
    end
    api.SetEnabled = wrapper

    return {{Disconnect = function()
        if api.SetEnabled == wrapper then
            api.SetEnabled = original
        end
    end}}
end

Этот вариант заменяет Connect из учебного примера, а не добавляется вторым. Он рассчитан на его метод через двоеточие и отсутствие возвращаемых значений. Для другого API сохраните его способ вызова и результаты. Сначала выполните исходную функцию, затем emit: не записывайте неуспешное действие.

Перехват не увидит локальную копию функции, сохранённую до установки обёртки. Клиентский API имеет отдельный контекст; серверный аддон не перехватывает клиентские действия автоматически. Для таких систем нужен доверенный серверный API/сигнал. Не оборачивайте все методы подряд и не меняйте сторонние функции, которые вам не нужны.

Состояние и разовые эффекты

Для SetEnabled, цвета или положения ReplayOnSeek=true обычно имеет смысл: при восстановлении позиции HOTLINE повторяет команды состояния. Reset должен привести систему к понятной начальной точке.

Для разовой команды Fire, хлопушки или одноразового импульса оставьте ReplayOnSeek=false. При ручной перемотке такой эффект пропускается. При обычном прохождении времени команда выполняется; запуск с нуля исполняет команды на нуле. Это правило не запрещает повтор эффекта при новом запуске шоу. Если повтор опасен для логики вашей игры, проверяйте условия в реальном API.

Не запускайте эффекты из Resolve/Connect. Они подключают интеграцию, а не воспроизводят шоу. Не создавайте снимок, который сам активирует разовый эффект.

Надёжность и проверка перед выпуском

Инициализация аддона имеет 10-секундный предел регистрации. Не используйте бесконечные WaitForChild в Resolve/Connect. Если зависимость отсутствует, верните nil и перезапустите тест после её установки. Готовность HOTLINE и готовность аддона проверяются отдельно.

Validate, Run, Reset и обработчики сигналов делайте короткими и без ожиданий. Общие лимиты событий, очереди и бюджета команд действуют и для аддонов. HOTLINE подавляет обратную запись во время собственного dispatch/reset; не отправляйте отложенный emit через task.delay от команды воспроизведения — такое эхо выйдет за пределы подавления.

  1. Проверьте прямое управление своей системой без HOTLINE.
  2. Убедитесь, что GetAddons сообщает ready и Output не содержит ошибок.
  3. Запишите Timed и Capture, проверьте время и аргументы в Events.
  4. Сохраните, загрузите и воспроизведите шоу; число событий не должно расти от воспроизведения.
  5. Проверьте Stop, перемотку, повторный запуск и Snapshot, если он есть.
  6. Проверьте отсутствие зависимости, неверные аргументы и неправильный API.
  7. Проверьте реальную игру с несколькими игроками: стенд с заглушками не проверяет репликацию и физику приборов.

Модули Addons исполняются на сервере и считаются доверенным кодом. Не загружайте аддоны из произвольных клиентских данных и не добавляйте общий RemoteEvent «выполнить любой метод».
