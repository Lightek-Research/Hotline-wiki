Troubleshooting

Problem

What to check

The editor does not appear.

Check your actual Username or UserId in Config. DisplayName does not grant access. Restart the server after changing Config. Check Studio Output for errors.

Owner or Studio account is denied.

Access is explicit. Add that account to the whitelist.

“Editor is in use” appears.

Another authorized player owns the current session. One editor session is supported.

Record does nothing.

Select a cue first. Pause playback. In Capture, send a supported GLights command after arming.

Recording mode is not visible.

In Load, press Edit. Show hidden controls with Panels or Tab. Timed / Capture is in the transport row.

Capture blocks editing.

Send one command to complete Capture, or cancel recording first.

A cue plays duplicate commands.

Check Show → Recording. Append adds events; Replace starts a new take when the first command arrives. Inspect Events for unwanted commands.

The timeline says 1 s.

This is the initial derived length, not a maximum. Scroll or seek farther. If playback still stops at one second, check for outdated or duplicate scripts.

No audio plays.

Check the asset ID, Roblox audio permissions, local volume, and GlobalAudio. A song title alone does not supply audio.

Spectators cannot hear music.

Set Config.GlobalAudio to true, leave the SecuritySettings override nil, and restart. Check AudienceAudio is included in Scripts.

Save or load fails.

Check DataStore access, Output, the slot, and saved revision. Do not repeatedly click while a request is pending.

A dark dialog backdrop remains.

Press Esc or the dialog's Close button. If neither works, check that Controller and GUI are matching versions.

“Too many requests” appears.

Wait briefly and retry. Inspect custom code for loops or rapid repeated Remote calls.

Playback stops because of command backlog.

Reduce unusually dense command bursts and profile GLights. Do not raise scheduler budgets without measurements.

When reporting a bug, include the HOTLINE version, recording mode, steps to reproduce, whether the issue happens in Studio or a published server, and relevant Output errors. Remove private data from logs before sharing them.

Contact the developer

If the issue persists, report it through:

  • Telegram: @hoomlion.

  • Discord: hoomlion.

Include:

  1. Your HOTLINE version and whether this happens in Studio or a published experience.

  2. Reproduction steps: which screen, button, and recording mode you used.

  3. What you expected and what happened instead.

  4. A screenshot or short video and any relevant Output error.

  5. For an interface issue, the control number from the interface reference.

Do not send passwords, cookies, tokens, or other credentials.

New modes and features

ProblemWhat to check
Editing controls are missing in Load.This is playback mode. Press Edit on the compact toolbar.
Load is waiting for music.With a linked Workspace Sound, start it or press Play. Otherwise the saved Audio ID is used; with neither source the show runs without music.
A new take should replace previous events.Choose Show → Recording → Replace. Timed / Capture selects how to record, not whether to overwrite.
Follow stopped after manual paging.Previous / Next disables Follow. Turn it on again from the toolbar.
A group does not expand or ungroup as expected.Cue List expansion is visual only. Ungroup a selected group in Edit; older groups may not contain component metadata.
Buttons appear but do not respond.Ensure Controller, Server, Timeline and GUI come from one complete version. Check Output.
The show stops when the song ends.This is automatic stop. A show without music is stopped manually with Stop.
