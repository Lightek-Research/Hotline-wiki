Creating addons: a pyro example

Download the complete Pyro module · ZIP

This guide follows one complete example: a button enables/disables ParticleEmitter effects inside a Fire folder. First the button only controls the effect. Then we add HOTLINE recording and playback from cues.

Requires HOTLINE 0.14.0 or later. This is a continuous Enabled=true/false effect, not a one-shot ParticleEmitter:Emit() burst. Adapt it to your own system. See installing ready-made addons.

1. Prepare the effect and button

  1. Create a Fire folder in Workspace.
  2. Place your configured Part/Attachment objects with ParticleEmitter effects inside it. The addon finds all emitters, including nested descendants.
  3. Disable their Enabled property initially. Verify that enabling them manually produces a visible effect: configure Texture, Rate and other properties first.
  4. Create a Part named PyroButton in Workspace and add a ClickDetector inside it.

The paths should be Workspace.Fire and Workspace.PyroButton.ClickDetector. In Studio testing, left-click enables the effect and right-click disables it. Stay within the ClickDetector's MaxActivationDistance.

2. A normal button without recording

Before HOTLINE integration, a server Script inside PyroButton might look like this:

local folder = workspace:WaitForChild("Fire")
local click = script.Parent:WaitForChild("ClickDetector")

click.MouseClick:Connect(function()
    for _, object in ipairs(folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = true end
    end
end)

click.RightMouseClick:Connect(function()
    for _, object in ipairs(folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = false end
    end
end)

This only controls the effect. HOTLINE does not know which button was pressed. We will move button handling into an addon ModuleScript; disable/remove the old button Script so it cannot continue acting separately.

The snippets below explain the parts. To install the example, use the complete module in section 6. Do not create a separate Script for every snippet.

3. Move actions into functions

Use two functions callable both by the button and by playback. api.Folder is the Fire folder reference returned by Resolve.

local function turnOn(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = true end
    end
end

local function turnOff(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = false end
    end
end

Record the action “enable pyro” once, not each emitter's individual property change. Call emit after the action, outside the loop.

4. Record the button action

The loader passes emit to Connect. Call emit("On") or emit("Off") after the action succeeds. Timed retains the command's offset; the first command in Capture ends recording.

api.Click.MouseClick:Connect(function(player)
    if not canUse(player) then return end
    turnOn(api)
    emit("On")
end)

api.Click.RightMouseClick:Connect(function(player)
    if not canUse(player) then return end
    turnOff(api)
    emit("Off")
end)

In the full module, canUse checks the HOTLINE whitelist before enabling the effect. Without active recording, an authorized button still controls pyro but adds no cue events.

5. Add playback

The emit name must match its Commands key. When HOTLINE encounters @Pyro / On, it validates that there are no arguments and calls turnOn. Off calls turnOff.

Addon.Commands.On = {
    Validate = noArguments,
    Run = turnOn,
    ReplayOnSeek = true,
}
Addon.Commands.Off = {
    Validate = noArguments,
    Run = turnOff,
    ReplayOnSeek = true,
}

ReplayOnSeek=true is appropriate here because Enabled is state that seeking should restore. A one-shot Emit burst or pulse usually keeps it false. That requires a separate implementation for your system; it is not part of this continuous-effect example.

6. Complete addon code

Stop Play. Create a ModuleScript named Pyro in ServerScriptService → Hotline → Addons and paste the entire code below. Disable the old button Script from section 2.

-- HOTLINE 0.14.0+: continuous ParticleEmitter on/off example.
-- Install this ModuleScript as Hotline.Addons.Pyro.
local Addon = {Id = "Pyro", Version = 1, Enabled = true, Commands = {}}

local function turnOn(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = true end
    end
end

local function turnOff(api)
    for _, object in ipairs(api.Folder:GetDescendants()) do
        if object:IsA("ParticleEmitter") then object.Enabled = false end
    end
end

local function noArguments(args)
    assert(args.n == 0, "Pyro On/Off do not accept arguments")
end

Addon.Commands.On = {
    Validate = noArguments,
    Run = turnOn,
    ReplayOnSeek = true,
}
Addon.Commands.Off = {
    Validate = noArguments,
    Run = turnOff,
    ReplayOnSeek = true,
}

function Addon.Resolve(context)
    local folder = context.Resolve(context.Options.FolderPath or "Workspace.Fire")
    local button = context.Resolve(context.Options.ButtonPath or "Workspace.PyroButton")
    if not folder or not button then return nil end
    local click = button:FindFirstChildOfClass("ClickDetector")
    assert(click, "PyroButton needs a ClickDetector")
    return {Folder = folder, Click = click}
end

function Addon.Connect(api, emit, context)
    local scripts = context.Root.Scripts
    local settings = require(scripts.SecuritySettings)
    local canUse = require(scripts.AccessPolicy).new(context.Config, settings)

    return {
        api.Click.MouseClick:Connect(function(player)
            if not canUse(player) then return end
            turnOn(api)
            emit("On")
        end),
        api.Click.RightMouseClick:Connect(function(player)
            if not canUse(player) then return end
            turnOff(api)
            emit("Off")
        end),
    }
end

function Addon.Reset(api)
    turnOff(api)
end

return Addon

Resolve finds the effect folder and button. No separate pyro API module is required for this simple example: the on/off functions live in the addon itself. Connect registers button handlers and returns their connections. Reset disables all emitters when HOTLINE resets.

For a different system, replace turnOn/turnOff with its actual API calls. Do not paste StacyPilot's core:Record or RegisterResponse into HOTLINE: this contract uses emit and Commands.

7. Record and replay

  1. Restart Play and use a player on the HOTLINE whitelist.
  2. Create/select a cue in Edit, choose Timed and press Record.
  3. Left-click to enable pyro; after a couple of seconds, right-click to disable it.
  4. Press Pause in HOTLINE and open Events.
  5. Expect two commands: @Pyro / On and @Pyro / Off at different offsets.
  6. Save the show and press Play. The effect should enable and disable without button clicks.

For Capture, press Record and enable pyro once. Only On is stored at offset zero and recording finishes. To define the effect's duration you need both On and Off, so Timed is more convenient. Stop disables emitters through Reset.

Pressing On again records another action. Playback does not record itself: Run neither clicks the button nor calls emit.

Paths, status and troubleshooting

For different object names, merge this into the existing Config table:

AddonOptions = {
    Pyro = {
        FolderPath = "Workspace.Fire",
        ButtonPath = "Workspace.PyroButton",
    },
},

If AddonOptions exists, add Pyro inside it. Restart after path changes. Only one enabled addon may use Id Pyro. Keep the base package's PyroTemplate disabled.

Check status from an ordinary server Script:

local Api = require(game.ServerScriptService.Hotline.Scripts.Api)
assert(Api.WaitForReady(20), "HOTLINE is not ready")
local addons, err = Api.GetAddons()
if addons then
    local info = addons.Pyro
    print(info and info.state, info and info.error)
else
    warn(err)
end

The addon should become ready. It can initially be loading: WaitForReady waits for HOTLINE, not every addon. missing means a folder/button is absent; failed indicates a setup error such as a missing ClickDetector. See all statuses.

ProblemCheck
Button does nothingWhitelist, distance, ClickDetector, server errors and ready status.
Emitters are enabled but invisibleParticleEmitter Texture/Rate and the original effect without HOTLINE.
Effects work but no events appearSelected cue, Edit mode, active recording; old button Script disabled.
Many duplicate commandsKeep emit outside the emitter loop; avoid duplicate modules/handlers.
Pyro stays enabled after CaptureCapture stores only the first action. Record On and Off in Timed or press Stop.

Adapting this to your system

Id determines @Pyro and Config.AddonOptions.Pyro. Commands lists allowed actions. Validate receives unpacked arguments with an n field and must assert/error on invalid input. Run receives the result of Resolve and command arguments. Connect captures actions; Reset restores state.

This example has no arguments, so it checks args.n==0. For another system, validate each argument's count, type and range. The shared codec supports up to 12 arguments with HOTLINE's value/event limits.

Addons are trusted server code. Resolve/Connect register the integration, not activate effects. Keep handlers and Run short and non-yielding. Before release, test Timed/Capture, save/load, Stop, seeking and denied interaction from a player outside the whitelist.
