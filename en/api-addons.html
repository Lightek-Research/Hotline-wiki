API and automation

The server API lets another Script load a saved HOTLINE show, start its audio, pause playback and inspect state. An open operator GUI is not required. API and addon support were introduced in HOTLINE 0.14.0.

To connect other systems, see Installing and using addons. To build an integration, see Creating addons.

Your first automated launch

  1. Install HOTLINE in ServerScriptService and configure Config. The API module is ServerScriptService → Hotline → Scripts → Api.
  2. In Edit mode, create a short show, put commands in its first seconds and save it under the unique name API Test.
  3. Create an ordinary server Script in ServerScriptService. Use the server RunContext, not a LocalScript.
  4. Paste the following and start Play.
local SSS = game:GetService("ServerScriptService")
local Hotline = SSS:WaitForChild("Hotline", 10)
assert(Hotline, "Hotline folder not found")
local Api = require(Hotline:WaitForChild("Scripts"):WaitForChild("Api"))
assert(Api.WaitForReady(20), "HOTLINE is not ready")

local ok, result = Api.PlayShow("API Test", {
    UseConfiguredSound = false,
    Duration = 10,
})
if not ok then
    warn("HOTLINE: " .. tostring(result))
end

The show should start and stop after 10 seconds on the show clock. Duration is set explicitly for this test. A different show speed changes the real elapsed time before the deadline. If the operator GUI is open, it receives the show in Load mode.

This Script runs every time the test starts. Disable it after testing if you do not want automatic playback on startup.

Starting a test from Command Bar

Store the test code in a disabled ordinary Script named HotlineTest in ServerStorage. A Script does not execute while stored there. During Play, switch Studio to Server and launch a copy:

local test = game.ServerStorage.HotlineTest:Clone()
test.Enabled = false
test.Parent = game.ServerScriptService
test.Enabled = true

This runs API calls from a server Script. Use Command Bar to launch the prepared Script rather than pasting the full API test directly into Command Bar.

The client Explorer cannot see the contents of ServerStorage or ServerScriptService. Those scripts have not been deleted. If you see NetworkClient and empty server folders, switch to Server.

Selecting a saved show

PlayShow selects a saved lighting show, not an arbitrary audio ID. Pass a name or a saved slot:

local ok, result = Api.PlayShow("Opening")
-- Alternative: an exact save slot.
local okBySlot, resultBySlot = Api.PlayShow({Slot = "show_your_slot"})

Run only the variant you need: each call requests a new load/start. Names must match exactly and be unique. Prefer slots for repeated automation because they avoid scanning saved names. Duplicate names are rejected. A string matching an existing slot selects that slot first.

List slots using the Api variable initialized above:

local page, err = Api.ListShows(true)
while page do
    for _, show in ipairs(page.shows) do
        print(show.slot, show.name)
    end
    if not page.more then break end
    page, err = Api.ListShows(false)
end
if err then warn(err) end

The API has a separate page cursor from the GUI. Name search is capped at 200 pages of 50 keys. Loading another show is blocked while recording. Concurrent operations are rejected rather than queued. Do not call PlayShow every frame.

Transport and arming

The following calls assume an initialized Api. Invoke the command you need from your server event; these are not a sequence to run all at once.

CallBehavior
Api.PlayShow("Opening")Load a saved show and start it.
Api.ArmShow("Opening")Load in Load mode without immediately executing saved commands.
Api.Play()Start or resume the current show.
Api.Pause()Pause current playback.
Api.Stop()Stop and reset the position.
Api.GetState()Read current show state.
Api.GetAddons()Read addon registration states.

ArmShow can wait for a linked Workspace Sound to begin playing. If the Sound is already playing, synchronization begins on the next frame; stop it first to await a future trigger. Without a linked Sound, call Api.Play() after ArmShow.

Audio and launch options

local ok, result = Api.PlayShow({Slot = "show_your_slot"}, {
    RequireIdle = true,
    UseConfiguredSound = true,
    Duration = 52,
})
if not ok then warn(result) end
OptionMeaning
RequireIdleTrue rejects a launch while a show is playing. Default false.
UseConfiguredSoundDefault true: use a valid Workspace Sound mapped by Config.ShowSoundTriggers. False selects the saved show's internal audio.
DurationOptional positive duration for the internal show clock, including silent shows. Not used with a linked Workspace Sound.

Audio priority: linked Sound by slot/name → saved audio ID → silence. See ShowSoundTriggers and GlobalAudio settings.

PlayShow actively plays/resumes the linked Sound. ArmShow only prepares synchronization. Unattended internal audio is heard by players when GlobalAudio=true. False retains operator-only audio. Workspace Sound volume is controlled on that Sound.

Without Duration, the server attempts to determine internal track length. If this fails, provide Duration for reliable auto-stop. A silent show with no Duration has no audio-based stopping deadline.

Results, state and events

PlayShow, ArmShow, Play, Pause and Stop return ok, resultOrError. Always check ok. GetState, GetAddons and ListShows return data or nil, error.

local state, err = Api.GetState()
if state then
    print(state.name, state.slot, state.position, state.playing)
else
    warn(err)
end

State also includes recording, recordMode, readOnly, external, automated, speed, soundId and transport fields. WaitForReady(timeout) waits for the server API, default 10 seconds, allowed range 0–60. Addon readiness is checked separately.

Api.Events.ShowLoaded:Connect(function(state)
    print("Loaded:", state.name)
end)
Api.Events.PlaybackStarted:Connect(function(state)
    print("Started:", state.slot)
end)
Api.Events.PlaybackStopped:Connect(function(event)
    print("Stopped:", event.reason, event.state.position)
end)
Api.Events.Error:Connect(function(event)
    warn(event.operation, event.error)
end)
SignalPayload
ReadyAPI initialization. If subscribing later, use WaitForReady instead.
ShowLoaded, PlaybackStarted, StateChangedShow state. StateChanged reports state/mode transitions, not continuous position ticks.
PlaybackPaused, PlaybackStoppedTable with reason and state.
ErrorTable with operation and error.
AddonsChangedAddon status table.

BindableEvent commands are available as Api.Signals.PlayShow, ArmShow, Play, Pause and Stop:

Api.Signals.PlayShow:Fire("Opening")

Signals have no return value. Observe Events.Error and Output for failures. Use a normal method when you need ok directly.

Access and troubleshooting

The API trusts server code. The existing GUI whitelist remains active. If you expose a player button or RemoteEvent, check permissions on the server before calling the API. Do not grant arbitrary client-selected show execution without validation.

SymptomCheck
Hotline is not a valid member with Client in OutputClient execution. Use an ordinary server Script and Studio's Server context.
Infinite yield waiting for HotlineFolder name/location and execution context. The first example limits this wait to 10 seconds.
HOTLINE is not readyHotline.Scripts.Server must initialize. Inspect the first errors after Play starts, GLights and Config. Test from an ordinary server Script.
Saved show not foundSave in the same experience/store; check the exact name or Slot.
Duplicate show namesUse Slot.
Required addon unavailableInspect GetAddons and addon diagnostics.
Missing audio or auto-stopCheck source, audio permissions, GlobalAudio and Duration.
