Getting started

Requirements

  • Roblox Studio and permission to edit the experience.

  • A compatible GLights installation. HOTLINE calls its server-side API; it does not replace GLights.

  • The complete, updated HOTLINE model, including its GUI template.

  • Permission for the experience to use any selected audio asset.

Install a ready-to-use model

  1. Save a backup of your place and stop Play mode.

  2. Put the updated GLightTimeline model in ServerScriptService. Install only one copy.

  3. Keep Config directly inside GLightTimeline. Keep the working modules and the GUI template in GLightTimeline → Scripts.

  4. Edit the existing Config and set your access list. For example:

AdminUserIds = {},
AdminUsernames = {"YourUsername"},
GlobalAudio = true,

These are fields inside the existing return { ... } table. Replace YourUsername with your actual Roblox username. Do not replace the whole Config with this short example.

  1. Check GLightsName. The default is GLights, matching the GLights model in Workspace. The integration expects Scripts → Core → Main inside that model.

  2. Start a test using an explicitly authorized account. The experience owner and Studio do not bypass the access list.

The server copies the editor GUI only to allowed players. Other players receive the lightweight audio listener. One operator can own the editor at a time.

First test

Open a new show, add a cue, select Timed or Capture, and record a simple GLights command. Pause, return to the beginning, and press Play. Verify that the intended fixtures respond. Then test saving and loading a show.

For persistence testing, use a published test experience with DataStore access. If enabling Studio API access, use a separate test experience so Studio does not alter production saves.
