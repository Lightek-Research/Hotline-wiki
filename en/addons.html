Addons

An addon connects HOTLINE to another system: it captures that system's commands while recording and invokes its API during playback. GLights continues to work normally. One show can combine lighting, cameras, lyrics and lasers.

This feature requires HOTLINE 0.14.0 or later. A native addon is a ModuleScript inside Addons. The external products themselves must be installed separately.

Installing a ready-made addon

  1. Stop Play.
  2. Import the addon's .rbxmx and move its ModuleScript into ServerScriptService → Hotline → Addons.
  3. Install the external system and verify its API path.
  4. Restart Play and check addon status.
  5. Select/create a cue in Edit, start recording and operate the external system normally.

Install one copy per addon. A .luau file included in the archive is usually the same source for inspection, not an additional required module. Arbitrary StacyPilot addons are not automatically compatible; use a native HOTLINE port.

Available integrations

AddonDefault APIRecorded commands
LyricsServerScriptService.LyricsController.Scripts.ApiLineChanged text, replayed through Chat(text).
CamerasWorkspace.CameraSystem.ApiCamera, focus, FOV, blur, saturation, tilt, bars, blackout, transition/speed and shake.
AtomLazersWorkspace.Atom(Lazers).Core(api)ON/OFF, color, spinning and speed. Installed as a separate addon.

Lyrics and Cameras are ports of the supplied StacyPilot integrations. Their custom visual tracks are not reproduced: use HOTLINE's standard Events/Cue List.

PyroTemplate in the main package is a disabled template. It requires the actual pyrotechnics API; it is not a universal ready-made driver.

Paths and options

Add this inside the existing Config table. If AddonOptions already exists, merge the entries rather than creating a duplicate field.

AddonOptions = {
    Lyrics = {
        ApiPath = "ServerScriptService.LyricsController.Scripts.Api",
    },
    Cameras = {
        ApiPath = "Workspace.CameraSystem.Api",
        SnapshotOnRecord = false,
    },
    AtomLazers = {
        ApiPath = "Workspace.Atom(Lazers).Core(api)",
        SnapshotOnRecord = false,
    },
},

Omit these fields to use default paths. If an addon implements Snapshot, SnapshotOnRecord=true records its initial state at the start of Timed. Capture does not take a snapshot: it waits for your command.

Restart after changing paths or adding dependencies. An integration missing during initialization does not reconnect automatically later.

Timed and Capture

ModeBehavior
TimedCommands retain their offsets from the cue start. Pause finishes recording.
CaptureThe first command is stored at offset zero, then recording finishes automatically.

If one panel action emits several signals, Capture saves the first. It does not batch every parameter into a snapshot. Use Timed for a sequence.

Open the cue's Events. Addon targets begin with @: @Lyrics, @Cameras, @AtomLazers. Reserve this prefix rather than using it in GLights group names. Playback must not record its own commands again. A show with addon events requires the working integration; otherwise loading is rejected.

Example: AtomLazers

Keep the original Atom(Lazers) system in Workspace with Core(api) and Lazers. Put the new AtomLazers ModuleScript into Hotline.Addons. No original Core replacement is required.

This laser API has no signals, so the addon wraps methods on its server API table. After addon readiness, use DOT calls from ordinary server Scripts:

local Laser = require(workspace["Atom(Lazers)"]["Core(api)"])

Laser.ON()
Laser.CHANGECOLOR(Color3.fromRGB(255, 0, 0))
Laser.CHANGE_SPIN_SPEED(0.05)
Laser.SPIN_ON()
-- At the desired time:
Laser.SPIN_OFF()
Laser.OFF()

This is a list of calls, not a timed sequence: without waits they run immediately one after another. Record using your own panel/timed Script or the LaserTest supplied with the addon.

Color is Color3. Speed is a finite non-negative number in the original API's units. ON/OFF/SPIN_ON/SPIN_OFF take no arguments. OFF only disables beams. The original CHANGE_SPIN_SPEED immediately updates motor MaxVelocity; call SPIN_OFF afterward to ensure spinning is stopped.

A function reference cached before initialization, such as local on = Laser.ON, can bypass the wrapper. Call Laser.ON() through the API table. Client calls and direct Beam/Motor changes are not captured.

Reset and seeking

Each integration defines Reset. Lyrics clears text. Cameras clears focus, blackout and bars but retains the selected camera, because the supplied contract does not specify a reliable return-to-gameplay method. AtomLazers disables beams and spinning.

Seeking restores only commands whose developer enables ReplayOnSeek. This suits color and state. One-shot effects are skipped by default while restoring position. See Creating addons.

Checking status

Run from an ordinary server Script:

local Api = require(game.ServerScriptService.Hotline.Scripts.Api)
assert(Api.WaitForReady(20), "HOTLINE is not ready")

local addons, err = Api.GetAddons()
if addons then
    for name, info in pairs(addons) do
        print(name, info.state, info.error)
    end
else
    warn(err)
end

WaitForReady waits for HOTLINE, not every integration. During startup an addon may still be loading; check again later or subscribe to Events.AddonsChanged.

StatusMeaning
loadingInitialization is in progress.
readyRegistered and available.
missingExternal API not found; check path/dependency.
disabledReturned specification has Enabled=false.
failedInvalid specification, connection error or registration timeout; inspect Output.

Disable an addon with Enabled=false in its returned table and restart Play. A ModuleScript Enabled=false attribute also skips loading; such a module may be absent from the status list.

If no events appear, check addon readiness, Edit mode, selected cue, active recording, server execution and correct API calls. Report reproduction steps, Output and GetAddons to Telegram @hoomlion or Discord hoomlion.
