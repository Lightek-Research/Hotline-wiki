Security and performance

Server-controlled access

HOTLINE checks the authenticated player on the server before allowing control operations. A hidden GUI is not the security boundary. The whitelist can use numeric UserIds, actual Roblox usernames, or both.

The public audio listener receives only the information needed for music synchronization. It does not receive the project or permission to control lighting.

This policy covers HOTLINE's own control endpoint. Independent GLights remotes, third-party panels, and other server scripts require their own access checks. They are not automatically secured by installing HOTLINE.

Scheduling and networking

The editor's transport state goes only to the operator. During music playback, spectators receive a compact audio update about once per second. Recording sends incremental event batches rather than the entire accumulated show.

The scheduler limits work between commands and carries remaining commands into later frames. A sufficiently large backlog stops playback with an error instead of accumulating indefinitely. One expensive GLights command can still exceed the intended frame budget.

There is one server scheduler, not one per spectator. However, fixture effects, property replication, physics, and the rest of the experience contribute to the total cost.
